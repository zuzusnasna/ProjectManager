# 2026-09-22 Troubleshooting

## 1. Member Entity와 MemberResponseDTO 타입 불일치

### 문제 상황

회원 정보를 DTO로 분리하는 과정에서 Service의 반환 타입을 `MemberResponseDTO`로 변경했지만,
일부 코드에서는 기존의 `Member` Entity를 그대로 반환하면서 타입 불일치 문제가 발생했다.

예시:

```
필요한 타입: MemberResponseDTO
제공된 타입: Member
```

### 원인

기존에는 회원 정보를 `Member` Entity 자체로 반환했지만,
비밀번호가 응답에 포함되는 문제를 해결하기 위해 응답 전용 DTO를 적용하면서
Service와 Controller의 반환 타입을 함께 변경해야 했다.

### 해결

조회 또는 저장된 `Member` Entity를 `MemberResponseDTO`로 변환하는 메서드를 만들고,
Controller에는 DTO를 반환하도록 수정했다.

처리 흐름:

```
Member Entity
    ↓
toResponseDTO()
    ↓
MemberResponseDTO
    ↓
Controller 응답
```

응답 DTO에는 `id`, `loginId`, `name`, `role`만 포함하여
비밀번호가 API 응답으로 노출되지 않도록 했다.

## 2. HTTP 405 Method Not Allowed

### 문제 상황

Postman으로 API를 테스트하는 과정에서 다음 응답을 확인했다.

```
405 Method Not Allowed
```

### 원인

Controller에 정의한 HTTP 메서드와 Postman에서 실제로 요청한 HTTP 메서드가
일치하지 않으면 Spring MVC에서 `405` 응답이 발생한다.

예를 들어:

```java
@PostMapping
public MemberResponseDTO saveMember(...) {
    ...
}
```

위 API에 `GET` 또는 다른 메서드로 요청하면 정상적으로 처리되지 않는다.

### 확인 방법

Controller의 Mapping과 Postman의 요청 방식을 확인했다.

```text
POST   /members
GET    /members
GET    /members/{id}
PUT    /members/{id}
DELETE /members/{id}
```

각 API에 맞는 HTTP Method를 사용하여 테스트했다.

## 3. Request DTO와 Response DTO 분리

### 문제 상황

기존에는 Controller에서 `Member` Entity를 직접 요청과 응답에 사용했다.

Entity를 그대로 응답하면 DB에 저장된 비밀번호까지 API 응답에 포함될 수 있는 문제가 있었다.

### 해결

요청 데이터와 응답 데이터를 분리했다.

```text
Client
  ↓
MemberRequestDTO
  ↓
MemberService
  ↓
Member Entity
  ↓
Oracle Database
```

응답은 반대로:

```text
Oracle Database
  ↓
Member Entity
  ↓
MemberResponseDTO
  ↓
Client
```

이 구조를 적용하여 비밀번호가 응답 DTO에 포함되지 않도록 했다.
